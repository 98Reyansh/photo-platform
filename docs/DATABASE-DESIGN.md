# Database design

P0-03 adds the PostgreSQL table `Tenants`. P0-05 adds ASP.NET Core Identity account tables and `StudioMemberships`. P0-06 adds private photo metadata in `Photos`. Comments, likes, and subscriptions are not in the schema. A membership row links one user to one tenant. Photograph rows are visible only through the resolved studio. File bytes, storage keys, and original filenames are not database columns. A local filesystem adapter, when configured, keeps bytes outside the database and has no HTTP route.

## Tenant

The domain type is `PhotoPlatform.Domain.Entities.Tenant`. The application assigns the identifier with `Guid.CreateVersion7`, and the database does not generate it.

The slug is normalized before it is stored: trim, invariant lowercase, and only lowercase letters, digits, and single hyphens. `North-Studio` and `north-studio` are the same slug. The unique index is on that stored value.

| Column | PostgreSQL type | Rules |
| --- | --- | --- |
| `Id` | `uuid` | Primary key. Generated by the application. |
| `Name` | `character varying(200)` | Required. Trimmed. Maximum 200 characters. |
| `Slug` | `character varying(80)` | Required. Normalized. Maximum 80 characters. Unique through `IX_Tenants_Slug`. |
| `Status` | `character varying(32)` | Required. `Active` or `Suspended`. Check constraint `CK_Tenants_Status`. New tenants start as `Active`. |
| `CreatedAtUtc` | `timestamp with time zone` | Required. UTC. |
| `UpdatedAtUtc` | `timestamp with time zone` | Required. UTC. Set to the creation time until a later task changes a tenant. |

## Studio membership

The domain type is `PhotoPlatform.Domain.Membership.StudioMembership`. Identity account types stay in Infrastructure as `ApplicationUser`, an `IdentityUser<Guid>`. The context is `IdentityUserContext<ApplicationUser, Guid>`, so role tables are not created.

| Column | PostgreSQL type | Rules |
| --- | --- | --- |
| `Id` | `uuid` | Primary key. Generated by the application. |
| `UserId` | `uuid` | Required. Unique through `IX_StudioMemberships_UserId`. One membership per user. |
| `TenantId` | `uuid` | Required. Foreign key `FK_StudioMemberships_Tenants_TenantId` with delete behavior restrict. |
| `CreatedAtUtc` | `timestamp with time zone` | Required. UTC. |

Identity stores accounts in `AspNetUsers`, with `AspNetUserClaims`, `AspNetUserLogins`, and `AspNetUserTokens`. Email uniqueness is enforced by Identity's user validator (`RequireUniqueEmail`). The generated `EmailIndex` is the Identity default and is not a unique database index. Passwords are stored only as Identity password hashes.

## Photo metadata

The domain type is `PhotoPlatform.Domain.Photos.Photo`. The application assigns the identifier with `Guid.CreateVersion7`, and the database does not generate it. `TenantId` comes from the resolved studio, not from the request.

| Column | PostgreSQL type | Rules |
| --- | --- | --- |
| `Id` | `uuid` | Primary key. Generated by the application. |
| `TenantId` | `uuid` | Required. Foreign key `FK_Photos_Tenants_TenantId` with `ON DELETE RESTRICT`. Indexed by non-unique `IX_Photos_TenantId`. |
| `Title` | `character varying(200)` | Required. Trimmed by the domain type. Maximum 200 characters. |
| `Description` | `character varying(2000)` | Optional. Trimmed by the domain type. Blank becomes null. Maximum 2,000 characters. |
| `CreatedAtUtc` | `timestamp with time zone` | Required. UTC. |
| `UpdatedAtUtc` | `timestamp with time zone` | Required. UTC. Equals the creation time on insert. A successful details update sets it to that update's UTC time. |

`ApplicationDbContext` applies a global query filter to `Photo`: the studio must be resolved and `TenantId` must equal that studio. An unresolved studio matches no photo rows. `SaveChanges` and `SaveChangesAsync` reject a photo write when the studio is unresolved, when a new photo's tenant is not that studio, or when an existing photo's original or current tenant is not that studio. The boundary does not assign a different `TenantId`. `Tenant` and `StudioMembership` saves are not subject to that photo check.

`GET /api/v1/photos` reads that filtered set ordered by `CreatedAtUtc` descending and `Id` descending. A page requests at most 51 rows. Listing does not add a table, index, or migration.

## Migration

Name: `20261020135016_InitialTenants`.

Path: `src/backend/PhotoPlatform.Infrastructure/Persistence/Migrations/20261020135016_InitialTenants.cs`.

`Up` creates `Tenants`, `PK_Tenants`, `CK_Tenants_Status`, and unique index `IX_Tenants_Slug`.

Name: `20261024110924_AddStudioMembership`.

Path: `src/backend/PhotoPlatform.Infrastructure/Persistence/Migrations/20261024110924_AddStudioMembership.cs`.

`Up` creates the Identity user tables and `StudioMemberships`, including `PK_StudioMemberships`, unique `IX_StudioMemberships_UserId`, and `FK_StudioMemberships_Tenants_TenantId`. This migration was generated from the model. A previously reported test run exercised it through the guarded test path against `photo_platform_test`, where writes proceed only when the parsed database name is exactly `photo_platform_test`. The development database `photoplatform` was not migrated during the final read-only review. `PHOTO_PLATFORM_TEST_CONNECTION` was unset in that review environment, so the tests were not repeated then. This change does not run `database update` against `photoplatform`.

Name: `20261024122355_AddPrivatePhotoMetadata`.

Path: `src/backend/PhotoPlatform.Infrastructure/Persistence/Migrations/20261024122355_AddPrivatePhotoMetadata.cs`.

`Up` creates `Photos`, `PK_Photos`, `FK_Photos_Tenants_TenantId` with `ON DELETE RESTRICT`, and `IX_Photos_TenantId`. `Down` drops `Photos` only.

The first migration has been applied to the local development database `photoplatform`. P0-06 does not run `database update` against `photoplatform`. Guarded photo tests call `MigrateAsync()` only after the parsed database name is exactly `photo_platform_test`.

Integration tests use a separate database named exactly `photo_platform_test`. The connection string is supplied only through `PHOTO_PLATFORM_TEST_CONNECTION`. `Normalized_slug_is_unique_in_postgresql` calls `MigrateAsync()` only after `NpgsqlConnectionStringBuilder` accepts that database name. A malformed connection string, a missing database name, or any other database name is rejected before migration and before writes. The development database is not the test database.

## Connection string

Key: `ConnectionStrings:DefaultConnection`.

The API reads the standard configuration sources, including environment variables and user secrets. No real password is stored in the repository. `src/backend/PhotoPlatform.Api/connection-string.example.json` uses `Password=CHANGE_ME` as a placeholder.

A missing or blank connection string throws `InvalidOperationException` when a database operation creates `ApplicationDbContext`. The message names the configuration key and does not include a connection string. The process health endpoint does not create the context, so it still starts without PostgreSQL.

`GET /api/v1/health/database` is the only request that checks connectivity. It is not called from the process health endpoint or from ordinary requests. Failure returns HTTP 503 and `{ "status": "unhealthy" }` without credentials or exception text. Server logs record the exception type, or the PostgreSQL SQL state, and not the connection string.

## Local setup

Fedora package installation, Docker, user secrets, and the EF commands are in the repository `README.md`. Apply the migration only after a database exists:

```bash
dotnet tool restore
dotnet tool run dotnet-ef -- database update \
  --project src/backend/PhotoPlatform.Infrastructure/PhotoPlatform.Infrastructure.csproj \
  --startup-project src/backend/PhotoPlatform.Api/PhotoPlatform.Api.csproj
```

Inspect the result:

```bash
psql "host=localhost port=5432 dbname=photoplatform user=photoplatform" -c '\d "Tenants"'
```

Do not point `database update` at a production database from this local workflow.

## Tests

Domain tests cover required name and slug, maximum lengths, slug normalization, UTC timestamps, and UUID version 7. Photo domain tests cover required trimmed title, optional trimmed description, the 200- and 2,000-character limits, UTC timestamps, and an unchanged id, tenant, and creation time when an update is rejected.

Infrastructure tests build the EF model and assert required columns, lengths, the unique slug index, the status check, the presence of `20261020135016_InitialTenants`, the unique membership user index, the tenant foreign key, and the presence of `20261024110924_AddStudioMembership`. Photo model tests assert the `Photos` columns, the restrict foreign key, the tenant index, the fail-closed query filter, and the presence of `20261024122355_AddPrivatePhotoMetadata`. Those model tests do not open PostgreSQL. `PostgreSqlPhotoTests` runs only when `PHOTO_PLATFORM_TEST_CONNECTION` is set and the guard accepts `photo_platform_test`.

`Database_is_reachable` and `Normalized_slug_is_unique_in_postgresql` run only when `PHOTO_PLATFORM_TEST_CONNECTION` is set. They skip when it is unset. When it is set, both refuse to continue unless the parsed database name is exactly `photo_platform_test`. The in-memory EF provider is not used.
