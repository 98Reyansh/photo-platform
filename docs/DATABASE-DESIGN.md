# Database design

P0-03 adds one PostgreSQL table, `Tenants`. Identity, photographs, comments, likes, and subscriptions are not in the schema. A row in `Tenants` does not select a tenant for a request and does not make multi-tenancy operational. Photographs remain private by default; no photo table or access rule is stored yet.

## Tenant

The domain type is `PhotoPlatform.Domain.Entities.Tenant`. The application assigns the identifier with `Guid.CreateVersion7`, and the database does not generate it.

The slug is normalized before it is stored: trim, invariant lowercase, and only lowercase letters, digits, and single hyphens. `North-Studio` and `north-studio` are the same slug. The unique index is on that stored value.

| Column | PostgreSQL type | Rules |
| --- | --- | --- |
| `Id` | `uuid` | Primary key. Generated by the application. |
| `Name` | `character varying(200)` | Required. Trimmed. Maximum 200 characters. |
| `Slug` | `character varying(80)` | Required. Normalized. Maximum 80 characters. Unique through `IX_Tenants_Slug`. |
| `Status` | `character varying(32)` | Required. `Active` or `Suspended`. Check constraint `CK_Tenants_Status`. New tenants start as `Active`. |
| `CreatedAtUtc` | `timestamp with time zone` | Required. UTC. |
| `UpdatedAtUtc` | `timestamp with time zone` | Required. UTC. Set to the creation time until a later task changes a tenant. |

## Migration

Name: `20261020135016_InitialTenants`.

Path: `src/backend/PhotoPlatform.Infrastructure/Persistence/Migrations/20261020135016_InitialTenants.cs`.

`Up` creates `Tenants`, `PK_Tenants`, `CK_Tenants_Status`, and unique index `IX_Tenants_Slug`.

Apply this migration only after the development database `photoplatform` exists. The commands are in the repository README. Do not point `database update` at another database.

## Connection string

Key: `ConnectionStrings:DefaultConnection`.

The API reads the standard configuration sources, including environment variables and user secrets. No real password is stored in the repository. `src/backend/PhotoPlatform.Api/connection-string.example.json` uses `Password=CHANGE_ME` as a placeholder.

A missing or blank connection string throws `InvalidOperationException` when a database operation creates `ApplicationDbContext`. The message names the configuration key and does not include a connection string. The process health endpoint does not create the context, so it still starts without PostgreSQL.

`GET /api/v1/health/database` is the only request that checks connectivity. It is not called from the process health endpoint or from ordinary requests. Failure returns HTTP 503 and `{ "status": "unhealthy" }` without credentials or exception text. Server logs record the exception type, or the PostgreSQL SQL state, and not the connection string.

## Local setup

Fedora package installation, Docker, user secrets, and the EF commands are in the repository `README.md`. Apply the migration only after a database exists:

```bash
dotnet tool restore
dotnet tool run dotnet-ef -- database update \
  --project src/backend/PhotoPlatform.Infrastructure/PhotoPlatform.Infrastructure.csproj \
  --startup-project src/backend/PhotoPlatform.Api/PhotoPlatform.Api.csproj
```

Inspect the result:

```bash
psql "host=localhost port=5432 dbname=photoplatform user=photoplatform" -c '\d "Tenants"'
```

Do not point `database update` at a production database from this local workflow.

## Tests

Domain tests cover required name and slug, maximum lengths, slug normalization, UTC timestamps, and UUID version 7.

Infrastructure tests build the EF model and assert required columns, lengths, the unique slug index, the status check, and the presence of `20261020135016_InitialTenants`. Those tests do not open PostgreSQL.

`Database_is_reachable` and `Normalized_slug_is_unique_in_postgresql` run only when `PHOTO_PLATFORM_TEST_CONNECTION` is set. They skip when it is unset. The in-memory EF provider is not used.
